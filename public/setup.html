Set up Connect HubSpot

For the person who hosts this builder. Admins who use the builder never need this page. Full guide: hosting guide.

1Is sign-in ready?

Checking…

Open the builder

2Your redirect URL

HubSpot sends people back to this exact address after they approve. Put it in your HubSpot app's redirect URLs.

If you set APP_URL to a different address (for example your own domain), open this page on that address instead - the redirect URL must match APP_URL.

3Create the HubSpot app (once)

This file is the HubSpot app people approve when they click Connect HubSpot. It is already filled in with your redirect URL and asks only for read access.

  1. In HubSpot, create a personal access key: open the personal access key page. When you create it, make sure Developer projects is ticked, then click Copy next to the key. It is a long code - not a private app token that starts with pat-.
  2. Open the builder → Project → Import .uiex.json… → choose the file you downloaded.
  3. Click Publish (top right) → Publish to HubSpot tab → paste the personal access key. The builder checks it right away: it names the HubSpot account the key belongs to and says if Developer projects is missing (add it on the key page, then click Check again). Click Publish to HubSpot.
  4. Don't skip this: in HubSpot open Development → Projects → uiex-builder-connector → the app → Distribution → Begin publishing and sign HubSpot's Acceptable Use Policy (no Marketplace listing needed). Until you do, HubSpot refuses to install the app in every account, yours too, with "the app developer has not signed the acceptable use policy" - shown inside HubSpot's window, so the builder only sees the window close.
  5. On the app's Auth tab, copy the Client ID and Client secret.

Prefer the HubSpot CLI? Use the hubspot-app/ folder of the project instead (see the guide).

4Add the settings to your hosting

In your hosting provider's Environment variables screen, set:

  • HUBSPOT_CLIENT_ID - the Client ID from step 3
  • HUBSPOT_CLIENT_SECRET - the Client secret from step 3
  • SESSION_SECRET - 48 random characters: make one here (Render makes one for you)
  • APP_URL - this address (optional on Render and Vercel)
  • ALLOWED_PORTALS - optional: your HubSpot account number(s), comma separated. Only those accounts can then connect and deploy. Recommended.

Save, redeploy or restart, then click Check again in step 1.

5Test it like an admin

Open the builder in a private window and click Connect HubSpot. You should see HubSpot's permission screen and come back connected. If HubSpot shows a message instead, it never comes back to the builder - the builder then asks What did HubSpot show? and explains the fix. What each message means:

  • "The app developer has not signed the acceptable use policy" - you haven't signed it yet: step 3, item 4. This is the most common reason people can't connect.
  • Not allowed to install apps - the first person to connect from a HubSpot account installs the app for that account, and HubSpot only lets Super Admins (or users with App Marketplace access) do that. A Super Admin connects once; then everyone in that account can.
  • An install limit - an app without a Marketplace listing can be installed in up to 25 HubSpot accounts. Uninstall it where it's no longer used, or use ALLOWED_PORTALS so only your accounts install it.
  • A redirect URL error - the app's redirect URL must be exactly the one in step 2.
  • Nothing happens / the window is blocked - a pop-up blocker. The builder offers Continue in this tab.

People who can't connect can copy you a note from the builder that says what HubSpot showed. Publishing from the builder needs a personal access key with Developer projects from the account they're connected to; the builder checks that before uploading.
